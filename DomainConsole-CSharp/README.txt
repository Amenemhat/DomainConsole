DOMAIN CONSOLE — C# / WPF, версия 0.13

СТАТУС
Версия 0.9: C# / WPF. Сборка выполняется GitHub Actions на Windows.
Подключение к вашему домену и оформление на вашем экране требуют проверки.
Запуск: DomainConsole.exe. Сохраните папку Agent рядом с приложением.
Отметьте компьютеры, введите команду, нажмите «Выполнить команду».
Для нескольких шагов: раскройте «Шаги и параметры», затем «Добавить шаг» и «Выполнить набор шагов».
Результаты открываются автоматически; доступны копирование и сохранение TXT.
После перезапуска список компьютеров восстанавливается из локального кэша.
Выбор записи истории показывает её компьютеры и сохранённый вывод без подключения.
«Открыть задание» переключает на результат; «Результаты» обновляет выбранный ПК.
Обновление AD сохраняет связь компьютера с последним заданием.
При обновлении приложения перенесите папку Data из прежнего комплекта.
Настройки WSUS сохраняются один раз во вкладке «Настройки».
Вкладка WSUS: проверка без установки, установка, запрос отчёта и диагностика.
Источник клиента определяется его политиками. Проверка не переключает источник.
WUA подключение и поиск являются одним измеряемым этапом; журналы позволяют уточнить ошибку.
Проверка TCP не заменяет проверку HTTP/TLS/прокси.
Долгий этап (от 5 минут) выделяется, но это не диагноз зависания.
Приём отчёта проверяется отдельно по серверному времени LastReportedStatusTime.
Get-WindowsUpdateLog может выполняться долго; сбор диагностических данных ничего не сбрасывает.
«Проверить подключение» выполняет WinRM-проверку hostname/whoami без отправки задания.
При отказе в доступе проверьте учётную запись запуска и права WinRM на целевом ПК.
Приложение не меняет разрешения WinRM, ExecutionPolicy или политики аутентификации.

СОСТАВ
Console — настоящее Windows-приложение C# с WPF-интерфейсом, .NET 10.
Agent — C#-исполнитель для SYSTEM на целевом ПК, .NET Framework 4.6.2.
Shared — общие модели команд, результатов и истории.
После сборки запуск через Publish\DomainConsole.exe, без Start.cmd и Check.ps1.
Нет загрузки PS1 для запуска приложения, ExecutionPolicy не меняется.
PowerShell остаётся встроенным инструментом для WinRM, ваших PowerShell-команд,
диагностики WindowsUpdate и WSUS API. CMD выполняет ваши CMD-команды.
AppLocker, WDAC, ограниченные WinRM endpoints и политика безопасности сохраняются;
работоспособность используемых операций в вашей конфигурации надо проверить.

СБОРКА
На одном Windows-компьютере для разработки установите .NET 10 SDK x64.
Инструкция Microsoft: https://learn.microsoft.com/dotnet/core/install/windows
Нужен доступ к NuGet для пакетов и компонентов публикации.
Запустите Build.cmd. При успехе получите папку Publish, переносите её целиком.
.NET 10 для командного пункта включается в опубликованную поставку.
На целевых компьютерах нужен установленный .NET Framework 4.6.2 или выше.
Установщик приложения и цифровая подпись пока не подготовлены.

ФУНКЦИИ В КОДЕ
AD через LDAP без RSAT, дерево OU, поиск, отметки выбора; серверы наравне с ПК.
Редактор CMD/PowerShell, многострочные шаги, перестановка и редактирование.
Импорт TXT: выделить нужный фрагмент, «Добавить выделенное»; пояснения сами не удаляются.
Библиотека с категориями, описанием, избранным, поиском и JSON импортом/экспортом.
Шаблоны {{ImagePath}} и {{ImageIndex}} запрашиваются при запуске.
Перед запуском показываются команды, цели, источник и параметр перезагрузки.
Фоновая передача, задания Планировщика, SYSTEM, журналы, mutex на один ПК.
Задания остаются на целевом ПК после закрытия приложения.
История и библиотека сохраняются в Data рядом с приложением.
Восстановление результатов из истории, продолжение очереди, повтор и CSV.
Проверки DISM, SFC, восстановление из WIM, обновления через локальный WUA.
Возврат двух согласованных параметров источника и исходного состояния wuauserv.
Startup-задача возврата создаётся до изменения настроек.
Отмена после шага, скачивание журналов, запрос состояния WSUS через WinRM на сервере.
Перезагрузка через 15 минут только при включённом параметре и необходимости.
Проверка оставшихся обновлений после перезагрузки.

ПЕРВАЯ ПРОВЕРКА
После успешной сборки запустите EXE, загрузите AD, выберите один тестовый компьютер.
Добавьте hostname, оставьте Microsoft и автоперезагрузку выключенными.
Проверьте результат. Затем тест PowerShell: whoami; Get-Date.
Не начинайте с массового обновления или восстановления серверов.

ОГРАНИЧЕНИЯ И ОСТАВШАЯСЯ ДОВОДКА
Доменное удалённое исполнение проверяется в вашей среде.
Интерфейс проверен запуском и снимками на Windows; реальное исполнение проверяется в вашем домене.
Проценты извлекаются из вывода CMD; буферизация может задерживать их.
Вывод PowerShell записывается по завершении, не полноценный интерактивный терминал.
Нет принудительного прерывания процесса, пользовательских тайм-аутов и очистки по срокам.
Ожидание свежего отчёта WSUS автоматическим не является: показывает время отчёта.
Обновления после перезагрузки проверяются, следующий цикл пока повторяется вручную.
Временное переключение источника использует два согласованных параметра реестра;
дополнительные GPO, политики Windows 11, прокси и TLS надо проверять отдельно.
Не гарантируется автоматическая диагностика первопричины ошибки обновления.
Длинные команды управления могут упираться в предел аргументов Windows.
После аварии статус Running может остаться; пока сверяйте Updated и Планировщик.

Прежний PowerShell-комплект 0.1 не используется и не требуется.

Интерфейс 0.7: компьютеры внутри дерева OU, поиск слева, боковые вкладки и действия, общая шапка выбранного ПК, полупрозрачный прогресс в дереве. Ширина дерева и высота панелей WSUS регулируются разделителями.

Версия 0.8: вкладки библиотеки и отдельного вывода заменены общим редактором и результатом на вкладке Команды. Разделитель сохраняет пропорции. Подсказки содержат сохранённые и ранее введённые команды; новые команды сохраняются автоматически после подтверждённого успешного завершения хотя бы на одном ПК (все шаги с кодом 0). Журналы команд и WSUS разделены, в том числе после перезапуска. Ширина рабочих панелей определяется окном, а не длиной текста.

Версия 0.8: повторяющиеся строки прогресса DISM/SFC обновляются одной строкой. Диагностика и ошибки сохраняются; полный поток stdout доступен в файлах *.stdout.raw при скачивании журналов. Переносимый EXE включает .NET и WPF.

Версия 0.9: выбор OU с дочерними подразделениями и частичным состоянием галочки; активность отображается у всех родительских ветвей, включая свёрнутые. Строка отчёта WSUS показывается только в заданиях WSUS. Исправлен захват смешанного OEM/UTF-8/UTF-16LE вывода SFC и обновление строки процентов. Исходные байты сохраняются в *.stdout.bin/*.stderr.bin, читаемый полный вывод — *.stdout.raw. Новые задания используют новый исполнитель; старый повреждённый текст автоматически не восстанавливается.
Кнопка «Диагностика DISM / SFC» читает процессы, состояние задания, последние 80 строк CBS/DISM и время изменения журналов; сохраняет TXT в Data/Diagnostics. Не завершает процессы и не изменяет систему. Накопленное CPU-время следует сравнить на двух снимках. В шапке отдельно показывается возраст последнего вывода и изменения процента: heartbeat агента не доказывает продвижение команды.
Обновление: закройте консоль, замените EXE и папку Agent, сохранив Data. Не удаляйте задания на целевых компьютерах; ранее запущенные работы продолжаются со старым исполнителем.

Версия 0.10: исправлены начальные пустые UTF-16 строки SFC, тест включает их и разделение байтов по блокам. Для ненулевого exit-кода показываются десятичный и hex-код с предварительным объяснением. Если heartbeat устарел более двух минут, задача Планировщика Ready/Disabled и исполнитель отсутствует, состояние становится «Нужно вмешательство», без выдуманного кода DISM и без автоматического перезапуска. Длительный живой процесс не считается завершённым только из-за остановки процентов.

Версия 0.13: имя ПК открывает результат, отдельная галочка задаёт цели. Одно окно подтверждения для команд, сканирования, установки и запуска диагностики WSUS: по умолчанию текущий ПК; массовые цели выбираются явно, после принятого массового запуска галочки снимаются. Отмена и запуск на текущем ПК сохраняют галочки. Просмотр и скачивание результатов относятся к текущему ПК.
Основной результат и длительность фиксируются до автоматической диагностики. Метаданные DiagnosticStatus/Started/Ended отделены от основного задания; опрос продолжается до завершения сбора. Сбор WindowsUpdate.log ограничен 5 минутами, завершается только собственная группа диагностических процессов. DISM/SFC/установка не прерываются. Самостоятельно запущенный шаг WindowsUpdate.log тоже ограничен 5 минутами. Автосбор использует ETL, изменённые с начала задания минус 15 минут.
Кнопка диагностики читает CBS/DISM, доступные несжатые ротации, события Windows Update и журнал задания от начала задания минус интервал в настройках до снимка; без задания — последний час. Чтение ограничено 90 сек, до 30 000 последних строк на файл; ограничения явно указаны, CAB не распаковываются. Полный собранный TXT сохраняется до сокращения повторов, исходные файлы ПК не изменяются. Просмотр сокращает только соседние идентичные сообщения с сохранением первой/последней строк и количества. Разные пакеты и HRESULT не объединяются.
Все кнопки снабжены подсказками. Источник Microsoft вынесен под редактор, сетевые блокировки Kerio не меняются. Коды 12002 и 0x80072EE2 сопровождаются предложением проверить доступ из SYSTEM, Kerio, прокси и политики; причина не устанавливается только по коду.
Данные сервера WSUS представлены компактно с цветом: красный — ошибка, жёлтый — замечания/устаревший отчёт, зелёный — свежие данные без замечаний. Неустановленные обновления сводки не обязательно одобрены и применимы. Значки дерева относятся к текущему разделу и последнему заданию; успех запроса отправки не означает получение отчёта сервером.
Новая версия не заменяет исполнитель в ранее запущенном задании. Для старых терминальных записей таймер замораживается по времени последнего результата, диагностика старого исполнителя отмечается отдельно, новый лимит к старому процессу не применяется.

Версия 0.13: журнал разделён на раскрываемые группы, доступны поиск/фильтры и автопрокрутка. Повторы WindowsUpdate сворачиваются, исходные журналы доступны в скачанном комплекте. Метки UTC отображаются в местном часовом поясе консоли; записи системных логов без зоны считаются местным временем целевой машины.
Собственный ПК: локальное создание задания SYSTEM, чтение и скачивание результатов; требуется запуск от администратора. Последний просмотренный ПК, поиск, раскрытые ветви и вкладка сохраняются в Data/view-state.json. Галочки массового выбора не восстанавливаются.
После проверки/установки обновлений серверный отчёт повторно читается около двух минут. Свежесть по времени не доказывает связь с конкретной командой. Счётчики всех неустановленных/неизвестных обновлений не делают успешный поиск ошибочным.

0.13: единый тёмный журнал, контрастные заголовки, кнопка копирования только раскрытого/отфильтрованного текста. Диагностика отчёта отправляет запрос отчётности без поиска/установки, собирает клиентскую политику/идентичность и IIS/HTTPERR/события WSUS. Отсутствие запроса в прочитанных файлах не доказывает блокировку, HTTP 200 не подтверждает приём содержимого. Данные и ограничения сохраняются в Data/Diagnostics.
Клиент: общий исполнитель в Agent/<SHA256>, одна копия на используемую версию; старые версии сохраняются только при ссылках процессов/заданий. Основные задания удаляются по завершении; Restore/Verify защищены. Одно ежедневное задание DomainConsoleCSharp-Maintenance выполняет очистку. Неизвестные/активные состояния, ожидающие перезагрузки и восстановления, папки с ссылками не удаляются.
Полные журналы автоматически копируются в Data/Logs, проверяются SHA256; только завершённому заданию передаётся archived.json. Клиент хранит полученные журналы 7 дней после подтверждения, неполученные — 30 дней после окончания; сроки настраиваются, передаются при следующем запуске. История в Data не удаляется. Старые копии агентов и готовые задания очищаются при следующем запуске задания новой версией.

0.14: очистка очереди отчётности с необязательной копией; диагностика отказов WSUS по ID; привязка диагностики к заданию; последние IIS/ETL независимо от LastWriteTime. Копии ReportQueue_* сохраняются по запросу и удаляются вручную после диагностики.

0.15: действия с журналом перенесены к поиску; настройки в шапке; диагностика сгруппирована; копия очереди выбирается в подтверждении восстановления; автопрокрутка в настройках. Активный IIS-журнал читается с FileShare.ReadWrite/Delete; непроверенные запросы явно помечаются.
