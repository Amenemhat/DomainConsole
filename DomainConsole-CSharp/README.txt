DOMAIN CONSOLE — C# / WPF, исходный проект 0.2

СТАТУС
Версия 0.5: C# / WPF. Сборка выполняется GitHub Actions на Windows.
Подключение к вашему домену и оформление на вашем экране требуют проверки.
Запуск: DomainConsole.exe. Сохраните папку Agent рядом с приложением.
Отметьте компьютеры, введите команду, нажмите «Выполнить команду из редактора».
Для нескольких шагов: «Добавить в последовательность», затем «Выполнить последовательность».
Результаты открываются автоматически; доступны копирование и сохранение TXT.
После перезапуска список компьютеров восстанавливается из локального кэша.
Выбор записи истории показывает её компьютеры и сохранённый вывод без подключения.
«Открыть задание» переключает на результат; «Получить результаты» обновляет выбранный ПК.
Обновление AD сохраняет связь компьютера с последним заданием.
При обновлении приложения перенесите папку Data из прежнего комплекта.
Настройки WSUS сохраняются один раз во вкладке «Настройки».
Вкладка WSUS: проверка без установки, установка, запрос отчёта и диагностика.
Источник клиента определяется его политиками. Проверка не переключает источник.
WUA подключение и поиск являются одним измеряемым этапом; журналы позволяют уточнить ошибку.
Проверка TCP не заменяет проверку HTTP/TLS/прокси.
Долгий этап (от 5 минут) выделяется, но это не диагноз зависания.
Приём отчёта проверяется отдельно по серверному времени LastReportedStatusTime.
Get-WindowsUpdateLog может выполняться долго; сбор диагностических данных ничего не сбрасывает.
«Проверить подключение» выполняет WinRM-проверку hostname/whoami без отправки задания.
При отказе в доступе проверьте учётную запись запуска и права WinRM на целевом ПК.
Приложение не меняет разрешения WinRM, ExecutionPolicy или политики аутентификации.

СОСТАВ
Console — настоящее Windows-приложение C# с WPF-интерфейсом, .NET 10.
Agent — C#-исполнитель для SYSTEM на целевом ПК, .NET Framework 4.6.2.
Shared — общие модели команд, результатов и истории.
После сборки запуск через Publish\DomainConsole.exe, без Start.cmd и Check.ps1.
Нет загрузки PS1 для запуска приложения, ExecutionPolicy не меняется.
PowerShell остаётся встроенным инструментом для WinRM, ваших PowerShell-команд,
диагностики WindowsUpdate и WSUS API. CMD выполняет ваши CMD-команды.
AppLocker, WDAC, ограниченные WinRM endpoints и политика безопасности сохраняются;
работоспособность используемых операций в вашей конфигурации надо проверить.

СБОРКА
На одном Windows-компьютере для разработки установите .NET 10 SDK x64.
Инструкция Microsoft: https://learn.microsoft.com/dotnet/core/install/windows
Нужен доступ к NuGet для пакетов и компонентов публикации.
Запустите Build.cmd. При успехе получите папку Publish, переносите её целиком.
.NET 10 для командного пункта включается в опубликованную поставку.
На целевых компьютерах нужен установленный .NET Framework 4.6.2 или выше.
Установщик приложения и цифровая подпись пока не подготовлены.

ФУНКЦИИ В КОДЕ
AD через LDAP без RSAT, дерево OU, поиск, отметки выбора; серверы наравне с ПК.
Редактор CMD/PowerShell, многострочные шаги, перестановка и редактирование.
Импорт TXT: выделить нужный фрагмент, «Добавить выделенное»; пояснения сами не удаляются.
Библиотека с категориями, описанием, избранным, поиском и JSON импортом/экспортом.
Шаблоны {{ImagePath}} и {{ImageIndex}} запрашиваются при запуске.
Перед запуском показываются команды, цели, источник и параметр перезагрузки.
Фоновая передача, задания Планировщика, SYSTEM, журналы, mutex на один ПК.
Задания остаются на целевом ПК после закрытия приложения.
История и библиотека сохраняются в Data рядом с приложением.
Восстановление результатов из истории, продолжение очереди, повтор и CSV.
Проверки DISM, SFC, восстановление из WIM, обновления через локальный WUA.
Возврат двух согласованных параметров источника и исходного состояния wuauserv.
Startup-задача возврата создаётся до изменения настроек.
Отмена после шага, скачивание журналов, запрос состояния WSUS через WinRM на сервере.
Перезагрузка через 15 минут только при включённом параметре и необходимости.
Проверка оставшихся обновлений после перезагрузки.

ПЕРВАЯ ПРОВЕРКА
После успешной сборки запустите EXE, загрузите AD, выберите один тестовый компьютер.
Добавьте hostname, оставьте Microsoft и автоперезагрузку выключенными.
Проверьте результат. Затем тест PowerShell: whoami; Get-Date.
Не начинайте с массового обновления или восстановления серверов.

ОГРАНИЧЕНИЯ И ОСТАВШАЯСЯ ДОВОДКА
Доменное удалённое исполнение проверяется в вашей среде.
Тема оформления написана в XAML, визуальная проверка Windows ещё не выполнена.
Проценты извлекаются из вывода CMD; буферизация может задерживать их.
Вывод PowerShell записывается по завершении, не полноценный интерактивный терминал.
Нет принудительного прерывания процесса, пользовательских тайм-аутов и очистки по срокам.
Ожидание свежего отчёта WSUS автоматическим не является: показывает время отчёта.
Обновления после перезагрузки проверяются, следующий цикл пока повторяется вручную.
Временное переключение источника использует два согласованных параметра реестра;
дополнительные GPO, политики Windows 11, прокси и TLS надо проверять отдельно.
Не гарантируется автоматическая диагностика первопричины ошибки обновления.
Длинные команды управления могут упираться в предел аргументов Windows.
После аварии статус Running может остаться; пока сверяйте Updated и Планировщик.

Прежний PowerShell-комплект 0.1 не используется и не требуется.
