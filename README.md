# DomainConsole 0.42

[Готовый пакет и описание выпуска 0.42](https://github.com/Amenemhat/DomainConsole/releases/tag/v0.42).

Служебный опрос использует один клиентский сборщик с автономным пределом времени, штатной отменой и адресным завершением только собственных процессов чтения. Временная занятость не превращается в постоянный запрет; ошибки источников возвращают частичные данные, повторные сбои имеют паузы и отдельную диагностику. Блокировка сборщика не запрещает независимые ручные рабочие задания. Установка обновлений и процессы системных служб автоматически не останавливаются.

Короткие обращения WinRM получают подтверждение запуска и читают результат без удержания соединения на весь сбор. Таймеры объединяют одинаковые запросы и не создают новую ошибку на каждый пропущенный тик. В диалоге опроса доступны состояние, остановка, проверка и восстановление, а также адресная очистка подтверждённых старых Probe.

Текущий статус готовности рассчитывается совместно для главного результата, дерева, последних компьютеров и списка внимания. Свежий отчёт не отклоняется только из-за позднего окончания задания; неполные данные не дают ложный успех. В подписях адреса только IPv4.

Перед обновлением закройте **все старые экземпляры консоли** на управляющих компьютерах. Папку `Data` сохраните. [Изменения, проверка и ограничения](docs/releases/0.42.md).

## Возможности

### Компьютеры и удалённые задания

- Загрузка компьютеров и подразделений из Active Directory, поиск, выбор отдельных ПК и целых веток.
- Сворачиваемый список последних компьютеров, восстановление навигации и локальных данных после перезапуска.
- Выполнение CMD, PowerShell и последовательностей команд на выбранных целях; подтверждение области массового запуска.
- Сохранённые и недавние команды, параметры сценариев, подсказки при вводе.
- Явный режим CMD / PowerShell в редакторе и результате; предупреждение при распознанном несовпадении оболочки. Распознавание приблизительное, выбор остаётся за администратором.
- Раздельное выполнение команд и задач WSUS; отдельное выполнение простых команд управления перезагрузкой.
- Сохранение результатов на клиентах: закрытие консоли не останавливает переданное задание. После подключения результат можно прочитать снова.
- Запрос остановки после шага, отмена текущей операции и отдельные подтверждаемые варианты принудительной остановки там, где они поддерживаются исполнителем. Запрос остановки не равен подтверждённому завершению.
- Обработка недоступных целей без остановки остальных; согласование отсутствующего состояния и прерванных заданий после перезагрузки без автоматического повторного запуска.

### WSUS и обслуживание Windows

- Поиск, скачивание и установка применимых обновлений согласно политикам клиента и одобрениям WSUS.
- Этапы, проценты и результат по компьютерам; перезагрузка по умолчанию ручная, автоматическая включается явно.
- Запрос отправки отчёта и отдельное чтение серверных данных WSUS. Успешный запуск клиентской команды сам по себе не подтверждает получение отчёта сервером.
- Детализация ошибок WSUS по обновлениям и клиентской истории, когда данные доступны.
- Диагностика клиента, доставки отчётности, загрузки и установки, Defender, памяти и файла подкачки.
- Восстановление очереди отчётности, варианты очистки кэша с необязательной резервной копией, перезапуск выбранных служб.
- Снимки BITS с состоянием, объёмом, источником и скоростью; отдельное отображение фоновой очереди, не меняющее прогресс завершённого задания.
- Повышение приоритета выбранной загрузки BITS и возврат исходного приоритета. Ограничения сервера и сети сохраняются.
- Необязательное однократное автовосстановление остановившейся загрузки: выключено по умолчанию; требуется непрерывное наблюдение без движения и отсутствие признаков установки.
- DISM и SFC через встроенные сценарии или свои команды. Временное переключение источника восстановления Microsoft возвращает сохранённые параметры; доступ через сетевой шлюз остаётся отдельной настройкой.

### История и журналы

- Отдельная строка истории на каждый компьютер, включая массовые задания.
- Фильтры «Команды / WSUS / Всё», поиск клиента и команды, сортировка по дате, клиенту, результату и длительности.
- Просмотр полного сценария, копирование, подготовка правки и повторный запуск новым заданием.
- Группы журнала, цветовые акценты, подсветка поиска, сокращение повторов и компактный вывод CBS с контекстом.
- Копирование раскрытых разделов, экспорт и скачивание полных исходных журналов.
- Очистка завершённых заданий планировщика и неиспользуемых версий исполнителя; сроки хранения результатов настраиваются.

## Запуск и обновление

1. Скачайте готовый пакет Windows x64 и распакуйте целиком. Для запуска готовой сборки компилятор не нужен.
2. Оставьте `DomainConsole.exe` и каталог `Agent` рядом. Запускайте под доменной учётной записью с правами на целевые компьютеры. Для обслуживания собственного ПК требуется запуск от имени администратора.
3. Загрузите компьютеры из AD. Для серверных отчётов задайте адрес WSUS в настройках.
4. Перед запуском проверьте оболочку, цели и параметры команды.

При обновлении закройте приложение, замените **DomainConsole.exe и каталог Agent**, сохраните **Data**. Не копируйте чужую папку Data поверх своей. Уже работающие задания используют прежний исполнитель до завершения.

На клиентах используются WinRM / PowerShell Remoting и планировщик Windows; локальный C#-исполнитель запускается от SYSTEM. Постоянная служба агента не устанавливается. Требуются соответствующие доменные разрешения, доступность WinRM и административный доступ к WSUS. Пакет не содержит паролей и не настраивает доменную инфраструктуру вместо администратора.

## Новое в 0.30

- Устаревшие требования перезагрузки снимаются по новой загрузке или свежей полной проверке без флагов; ошибки опроса отделены от состояния сети и записываются в журнал без повторов.
- Отключённые записи AD видны отдельным значком и серым именем; массовые операции их пропускают. Есть фильтр с количеством и сохраняемое скрытие.
- После очистки кэша запускаются все согласованные службы, поиск и запрос отчёта. Режим «Полное обслуживание…» продолжает установку после подтверждённой перезагрузки, сохраняет сценарий и ограничивает циклы; перезагрузка разрешается отдельно.
- Сохраняемое ожидание отчёта WSUS и список «Требуют внимания» помогают завершать обслуживание независимо от выбранного клиента.
- Автоматическое восстановление отчётности: старый отчёт и подтверждённая старая очередь → одна очистка EventCache → поиск и запрос отчёта без установки. Занятые операции не прерываются; Download/DataStore и политики не меняются. Можно отключить в настройках отчётности.

- После назначенной перезагрузки проверяется новая загрузка Windows с учётом задержки, затем после настраиваемой паузы обновляются статусы. Можно явно включить один поиск обновлений без установки и следующей перезагрузки. Наблюдение сохраняется и отменяется отдельно.
- Журнал показывает фактическую причину сбоя подготовки. Если поиск/установка не начинались, программа не собирает лишний CBS и не ожидает отчёт этой операции. Успешный внутренний вывод планировщика скрыт.
- Отдельное подтверждаемое действие для зависших служб: выбор PID, проверка состава служб, времени создания и критичности процесса, восстановление служб. Критические процессы и общие процессы с посторонними службами не завершаются.

## Новое в 0.27

- Подтверждённая необходимость перезагрузки имеет приоритет основного значка. После задания проверяются WUA API и флаги Windows Update, CBS и ожидающих файловых операций; сохраняются источник, время и ограничения проверки. Сопутствующие ошибки остаются в журнале.
- Серверный отчёт, полученный до завершения установки, не выдаётся за подтверждение её результата. Подробные ошибки не повторяются одновременно в журнале и серверной сводке.
- Адрес подключения выбранного ПК: имя AD или отдельный IPv4/IPv6. Меняется через «Подключение» → «Адрес подключения…» либо меню компьютера. История и идентичность WSUS остаются у того же клиента.
- Плюс рядом с поиском добавляет клиента по IP в сохраняемую ветку «Ручные подключения». Перед сохранением проверяются доступ и имя клиента; при совпадении с существующей записью предлагается использовать её.
- Учётные данные IP-подключения действуют только на сеанс. Поддержаны настроенный HTTPS с проверкой сертификата либо HTTP с явным разрешением конкретного адреса TrustedHosts. Настройки не ослабляются автоматически.
- Перед операциями по IP сверяются имя и MachineGuid. Задания сохраняют исходный адрес; для того же подтверждённого клиента его можно явно обновить в параметрах без повторного запуска задания.

## Новое в 0.25

- Единые значки состояния WSUS в дереве и списке работы, независимо от открытой вкладки. Результаты команд остаются в своих журналах и истории.
- Постепенное чтение статусов всех загруженных компьютеров с сервера WSUS: по 10 ПК с паузой 2 секунды, один запрос одновременно; сначала компьютеры в работе, затем недавние. По умолчанию при открытии и раз в 24 часа; интервал 1–168 часов, автоматическое чтение можно выключить. Кнопка обзора позволяет остановить его и запустить заново. Проверки, установка и восстановление на клиентах не запускаются.
- Фильтр нескольких статусов со счётчиками; добавить в работу можно любую категорию. «Показать», «Отметить» и «Добавить в работу» — разные действия. Перед отметкой или добавлением показывается список. Область выбирается явно: весь список либо текущее подразделение с потомками. Счётчики учитывают область и текстовый поиск; категории могут пересекаться. В подтверждении указаны область, категории и количество целей.
- Добавленные в работу компьютеры сохраняются наверху списка недавних без дубликатов. Добавление само по себе не запускает команды и не меняет галочки.
- Обычное нажатие на имя открывает компьютер; Ctrl по имени переключает его галочку, Shift по галочке отмечает видимый диапазон. Работает в дереве и списке работы; скрытые диапазоном ПК не отмечаются.
- Кнопка перезагрузки текущего ПК в шапке: задержка, сообщение, явное разрешение принудительного закрытия приложений и отмена назначенного этой кнопкой перезапуска. Галочки остальных ПК не влияют на цель. Перезапуск идёт через независимую очередь управления. После ожидаемого срока консоль проверяет возврат клиента примерно раз в минуту (до 48 часов), читает время загрузки и флаг необходимости перезагрузки WUA, затем перечитывает данные сервера. Поиск и установка при этом не запускаются; наблюдение сохраняется после закрытия консоли. Более новый результат клиента учитывается отдельно от прежнего серверного снимка.

| Значок | Значение |
|---|---|
| Зелёная галочка | Свежий отчёт; необходимых обновлений нет |
| Серые часы | Сохранённый или устаревший отчёт; восстановления сам по себе не требует |
| Красный крест | Подтверждённая ошибка WSUS или более новое неуспешное задание, если нет подтверждённого требования перезагрузки |
| Оранжевое предупреждение | Нуждается в проверке; причина указана в подсказке |
| Круговая стрелка | Требуется или назначена перезагрузка; эти состояния подписываются отдельно |
| Перечёркнутый круг | Клиент не найден в WSUS |
| Значок связи / замок | Последняя попытка WinRM неудачна / отказано в доступе |
| Вопросительный знак | Данных недостаточно |

Недоступность WinRM не доказывает, что компьютер выключен. Чтение WSUS не проверяет доступность клиента. В подсказке указаны время получения данных и время последнего клиентского отчёта — это разные события. Давность не превращает известную ошибку в успешный результат. Неудачное чтение сервера сохраняет предыдущий снимок и показывает причину ограничения.

Реализация и проверки: [Issues #1–5](https://github.com/Amenemhat/DomainConsole/issues?q=is%3Aissue+is%3Aclosed).

## Исходники, проверки и выпуски

Актуальный код находится в [`DomainConsole-CSharp/`](DomainConsole-CSharp/). ZIP `DomainConsole-Source.zip` в корне — исторический снимок ранней версии, не источник текущих сборок.

Консоль: C# / WPF, .NET 10. Исполнитель: C#, .NET Framework 4.6.2. Для самостоятельной сборки на Windows используйте `DomainConsole-CSharp/Build.cmd` и соответствующий SDK.

[Windows workflow](.github/workflows/build-windows.yml) собирает пакет и проверяет интерфейс, локальное выполнение от SYSTEM, чтение через WinRM, прогресс, отмену, параллельные очереди и диагностические сценарии. Проверки CI не заменяют проверку в конкретном домене.

Новые замечания оформляются в Issues с критериями приёмки. Обсуждение не запускает немедленный выпуск: изменения накапливаются, версия готовится по отдельной команде владельца. Порядок работы описан в [CONTRIBUTING.md](CONTRIBUTING.md), публикация — в [руководстве по релизам](docs/RELEASING.md).
