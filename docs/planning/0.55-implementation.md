# 0.55.0 — работа над первым этапом

Не является отчётом приёмки или разрешением публикации.

## Внесено в код

- `WsusSnapshot58`: отдельный сохранённый серверный снимок, один список клиентов и один общий запрос сводок. Эффективные одобрения читаются порциями по ID, без повторного перечисления всех компьютеров и вызова сводки для каждого. Обзор не запускает клиентский WinRM-обход. Ошибка не заменяет прежний результат нулём.
- `IdentityPolicy58`, `Identity58`, `IdentityRepair58`: наблюдения ID при обычных обращениях; различение серверных дублей имени и общего ID разных машин; отдельная карточка/фильтр; перерегистрация обнаруженных участников; запись попытки до передачи, проверка имени/UUID/сервера/ID на клиенте, резервная копия реестра, ожидание свободного установщика, новый поиск/отчёт, отдельное подтверждение регистрации.
- `HistoryRetention58`: раздельные сроки/счётчики категорий; сохранение незавершённых заданий и конфликтов; повреждённые строки не удаляются; атомарная замена файлов; последовательная фоновая запись.
- `OutputRetention58`: удаление старого подробного вывода и файлов подтверждённых локальных архивов, сохранение состояния задания/результатов; возраст и размер на клиента/общий размер; настройки.
- Даты получения результатов в заголовках; для старых данных явно используется сохранённое время результата. Ручная проверка получает свежий снимок вне очереди сборщика. Чтение status.json делает пять ограниченных повторов.

## Проверки и оставшиеся условия перед выпуском

- Добавлены автоматические сценарии: сроки/счётчики истории, активное задание, открытый конфликт, непонятная строка, повторная очистка; один общий ID, переименование/алиас, старое наблюдение, другой сервер; квоты вывода.
- Необходимы полная Windows-регрессия точного коммита и визуальная проверка всех режимов/тем/размеров, включая новые элементы.
- Необходимо проверить массовый серверный сбор на изолированном WSUS с 400+ клиентами, сравнение эффективных одобрений, отмену и неполный ответ; измерить нагрузку, число вызовов и время.
- Необходимо испытать перерегистрацию на изолированных клонах, потерю ответа/питания, занятость установщика, недоступного участника и позднее появление общего ID. Производственные клиенты для этого не используются.
- Алиасы адресов WSUS пока сравниваются консервативно: разные URL не объединяются автоматически. Клоны с одинаковым аппаратным UUID требуют ручной диагностики, а не автоматического сброса.
- Внутренний код установщика по связанным событиям требует отдельной доработки; общий HRESULT не выдаётся за доказанную причину.
- Ручная повторная попытка допускается после отсутствия активного задания; перед сбросом снова проверяются фактические ID/имя/UUID/сервер. Автоматический повтор передачи с неподтверждённым исходом запрещён.
- Очистка событий выполняется по записи и в периодическом обходе известных клиентов; подробный вывод очищается периодически. Сквозной тест конкуренции чтения/очистки и ограничений для всех видов диагностики ещё необходим.

Ни одна из этих записей не означает успешное испытание живого WSUS или готовность выпуска.
