# Следующий пакет правок и переход к серверному обзору WSUS

Согласование: 04.11.2026. Документ требований, не отчёт о реализации.

## Согласовано: идентичность и восстановление регистрации

- Отдельный фоновый обход клиентов ради SusClientId не создавать. Получать сервер из политики, SusClientId и подтверждённую идентичность машины при обычных обращениях к клиенту.
- Сохранять наблюдения с источником и временем. Сопоставлять ID внутри одного логического WSUS; учитывать алиасы адреса сервера. Не объединять компьютеры только по SusClientId: он может быть клонирован.
- Повторные обращения к одной машине по имени/IP не считать разными клиентами. Смена имени и старое наблюдение сами по себе не доказывают дубль. Проверять конфликт перед изменением клиента.
- Подтверждённый дубль: один SusClientId у разных, заново подтверждённых машин. Несовпадение имени серверной записи — сигнал проверки, а не самостоятельное основание сброса.
- При подтверждённом конфликте предусмотрено автоматическое восстановление и ручная кнопка перерегистрации. Сохранить прежние значения, не прерывать активную установку, сменить ID, запросить повторную авторизацию, свежий поиск и отправку отчёта. Подтвердить новый ID и ожидаемое имя непосредственно на сервере.
- Не удалять чужую запись WSUS и не очищать SoftwareDistribution как часть обычной перерегистрации. Само отсутствие клиента на сервере не является основанием смены ID.
- Ограничить автоматическое исправление одной попыткой на конфликт; сохранять фазу и результат между запусками, не генерировать новый ID при каждом опросе. Ручное восстановление остаётся отдельным действием.
- История: обнаружение конфликта, отложенное действие и его причина, старый/новый ID, запрос авторизации, ожидание серверной регистрации, подтверждение или ошибка; у всех событий время.

## Ранее согласованные требования к отображению и ручной проверке

- В заголовках результатов операций, команд и отчётов показывать время данных и время получения консолью. Открытие окна не обновляет эти даты. Неудачный запрос не делает старый результат свежим.
- Проверка связи вручную запрашивает IP подключения, пользователя, загрузку/аптайм и флаги перезагрузки вне очереди фонового опроса; не запускает обновления. Частичные результаты и ошибки каждого поля отражаются явно; прежние значения сохраняются с датой.
- Временная блокировка status.json требует ограниченного повторного чтения; не равнозначна ошибке установки. Техническое исключение — в подробностях, восстановление чтения — в истории.
- Диагностика установки должна показывать связанный с конкретной попыткой внутренний код установщика наряду с общим HRESULT. Совпадения только по времени недостаточно для назначения причины.

## Согласовано: первый этап архитектурного перехода

Начать с независимого чтения сервера WSUS и общего сохранённого снимка по клиентам. Подход согласован 04.11.2026; реализация и проверка ещё предстоят.

Текущий код WsusOverviewTransport.cs уже выполняет один удалённый вызов на пакет и получает список компьютеров, но внутри цикла по каждому клиенту вызывает GetUpdateInstallationSummary и Read-RequiredUpdates31. Это пакетирование транспорта, а не полностью общий запрос сводок.

Согласованный план:

1. Получить список серверных записей и сводки через WSUS API GetSummariesPerComputerTarget; один запуск сбора на сервер, ограниченные порции при большом объёме.
2. Сохранять сервер, ID записи, имя, IP/ОС из отчёта, времена синхронизации и отчёта, результат синхронизации и счётчики состояний обновлений. Группы и подробности требуют отдельных/дополнительных вызовов; не обещать весь объём одним API-вызовом.
3. Общую статистику NotInstalled не называть «К установке». Для этого необходима проверка применимости и эффективных одобрений именно для данного клиента. До завершения такого расчёта показывать неполноту, не ноль.
4. Точные списки необходимых/ошибочных обновлений получать отдельно ограниченными порциями: при изменении серверных данных, открытии клиента или явном запросе. Изменение одобрений и состава групп тоже требует пересчёта, даже если время отчёта не поменялось.
5. Все представления читают одно состояние; источник, время данных, время чтения и полнота сохраняются раздельно. Серверный обзор обновляет серверные сведения, но не объявляет WinRM доступным и не переписывает фактический результат клиентского задания.
6. Старый отчёт не перекрывает более новое наблюдение клиента. Нулевой серверный счётчик означает только результат WSUS на время отчёта. InstalledPendingRebootCount — серверное указание, не замена свежей проверке WUA/CBS на клиенте.
7. Ошибка запроса сохраняет предыдущий снимок с причиной и временем ошибки. Отсутствие записи подтверждается только успешным чтением соответствующей области сервера; неполная порция/таймаут не означает отсутствие компьютера.
8. Серверный обход не требует соединений с каждым клиентом, не запускает установок и не занимает ручной канал команд. Политика автоустановки остаётся в существующем исполнителе с проверкой текущей применимости.

Недоступные из одного отчёта WSUS данные: текущая доступность WinRM, текущий пользователь, фактический аптайм, живой прогресс задания, текущие флаги перезагрузки. IP и ОС с WSUS — последняя известная серверу информация, не доказательство текущего адреса подключения.

Приёмка первого этапа: 400+ клиентов, точность эффективных одобрений, неполные ответы и серверная ошибка, новые/отсутствующие записи, конфликт ID/переименование, сохранность прежних статусов при запуске, единое обновление всех представлений, отсутствие блокировки ручных команд. Измерить число API-вызовов, длительность и нагрузку до/после; не обещать ускорение без измерений.


## Выявление и обозначение дублирующихся регистраций

Пакетный серверный сбор используется также для проверки идентичности; отдельный фоновый обход клиентов ради поиска дублей не добавляется.

- Несколько серверных ID с одинаковым нормализованным полным именем — «Несколько записей WSUS / возможный дубль». Это могут быть старые регистрации после переустановки или перерегистрации, а не разные работающие машины.
- Один SusClientId у нескольких машин может выглядеть на WSUS как единственная запись с меняющимися именем/IP. Поэтому серверный список сам по себе не выявляет все клоны.
- При обычных обращениях к клиентам сохранять их ID и подтверждённую идентичность с временем. Один ID у разных заново подтверждённых машин одного логического WSUS — «Подтверждённый общий SusClientId».
- Несовпадение имени клиента и записи WSUS — «Требуется проверка идентичности». Смена имени, общий IP, DHCP и устаревшие наблюдения не являются самостоятельным доказательством дубля.
- Показывать отдельный признак конфликта в списке и карточке, фильтр конфликтов и подробности: связанные имена, ID, источник, время каждого наблюдения и следующее действие. Признак не подменяет состояние обновлений и доступность связи.
- Автоматическую перерегистрацию выполнять только после подтверждения конфликта по правилам выше; предусмотреть ручную кнопку. Несколько записей одного имени не дают основания автоматически удалять или объединять записи сервера.
- Приёмка: одинаковый ID у двух машин; одинаковое имя у старой и новой регистрации; переименование; смена IP; повторное обращение к одной машине через разные адреса; устаревшие наблюдения; неполный серверный ответ. Подтверждённый конфликт должен сохраняться и отображаться согласованно после перезапуска консоли.


## Дополнительно согласовано 04.11.2026

- При подтверждённом клонировании SusClientId перерегистрировать всех обнаруженных участников, а не только один клиент. Группировать по общему ID в пределах сервера, не по имени. Прежний общий ID сохранять как конфликтный: позднее обнаруженный участник также требует восстановления. Недоступные/занятые остаются в ожидании, старые серверные записи автоматически не удаляются.
- Обычные события: 30 дней и максимум 2000 на клиента; значимые результаты установки, ошибки, ручные действия, перезагрузки и перерегистрация: 180 дней и максимум 5000. Превышение любого ограничения запускает очистку старых записей категории.
- Подробные выводы/журналы: 14 дней, 20 МиБ на клиента, общий предел 2048 МиБ. Незавершённые задания и открытые конфликты защищаются; защищённые данные могут превышать лимит и не удаляются ради него.
- Текущие статусы, последний подтверждённый результат и структурированные результаты установок не зависят от очистки событий. Настройки лимитов доступны оператору. Очистка не блокирует интерфейс, повторяющиеся служебные события объединяются.
- Начата разработка 0.55.0 в ветке work/wsus58. Это не опубликованный выпуск; доступная пользователю предыдущая версия не заменяется до приёмки.
