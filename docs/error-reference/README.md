# Справочник кодов DomainConsole

Подготовлено 18.10.2026 по поручению пользователя, задача #41; интеграция в главный вывод — #40. **Это данные и прототип чтения справочника. Исполняемый код приложения не изменён, новый релиз не выпущен.**

## Покрытие

См. точные количества в [manifest.json](manifest.json). Индекс охватывает Windows Update, BITS, WinHTTP, Win32, COM/RPC, криптографию и обслуживание компонентов. Подробные русские карточки подготовлены отдельно для частых ошибок, включая PSFX, Defender и случаи из диагностики пользователей. Все карточки имеют статус `prepared_for_review`: это редакционный материал для интеграции, а не результат проверки каждого ремонта на реальном клиенте.

- [REFERENCE.ru.md](REFERENCE.ru.md) — человекочитаемый справочник с подробными карточками и техническим индексом.
- `cards.tsv` — редактируемый оригинал русских карточек: код, состояние, профиль диагностики, символ, объяснение, возможные причины, первое действие.
- `sdk-symbols.json` — извлечённые пары «число—техническое имя» из SDK и официальных таблиц COM/CBS. Историческое имя файла; там не только SDK.
- `win32-symbols.json` — значения Win32 с отдельным сопоставлением HRESULT_FROM_WIN32. Это не коды завершения любых программ.
- `catalog.json` — результат сборки для последующей интеграции. **Для кодов без русской карточки нет готового подробного объяснения/лечения.**
- `source-revisions.json` — ревизии официальных репозиториев на момент сбора. URL в записях удобны для чтения текущей документации, сами извлечённые пары зафиксированы в JSON.
- `manifest.json` — количества и SHA-256 основных данных.

Содержимое английских текстов SDK/таблиц массово не копируется. Сохраняются числовые значения, технические имена, ссылки и собственные русские объяснения. Источники определения и авторский диагностический вывод различаются. Заголовки SDK сохраняют свои исходные условия лицензии; библиотека win32metadata не перелицензирует их в MIT. Новые файлы этого каталога следуют лицензии проекта, где она применима.

## Как показывать в программе

Одна карточка в итогах: **код + символ → понятное значение → подтверждённое наблюдение из текущего задания → возможные причины → ближайшее действие**. Источники и технический контекст раскрываются отдельно. Никаких многократных отсылок «подробнее ниже». Раздел без новой информации скрывается.

Код из результата конкретного обновления приоритетнее общего кода WUA, а исходный код обработчика CBS/MSI/BITS уточняет его. Фоновую запись нельзя объявлять причиной только потому, что она встретилась рядом по времени. Для связывания нужны как минимум этап, временной интервал, обновление/ревизия и контекст вызова. Если связь не подтверждена — так и писать.

Пример: `0x800F0988 / PSFX_E_INVALID_DELTA_COMBINATION` — проблема подготовки дельта-компонентов. Если CBS называет конкретный файл, показывать его в карточке как доказательство этой попытки; не хранить имя пользовательского файла как универсальное свойство кода. `0x8024200B` и `0x80240022` могут быть обёртками этой причины, а не тремя разными неисправностями.

## Разные пространства кодов

| Значение | Правильное толкование |
|---|---|
| HRESULT `0x00000001` | `S_FALSE`; подробный смысл зависит от COM-метода |
| Exit code `1` | Контракт конкретной программы; не переводить автоматически в Win32/HRESULT |
| WUA ResultCode `1` | Операция выполняется, результат не окончательный |
| WUA ResultCode `2` | Успех; дополнительно читать HRESULT и RebootRequired |
| Event ID `182` | Нужен провайдер события; это не HRESULT |
| Win32 `1455` | `ERROR_COMMITMENT_LIMIT`; соответствующий HRESULT `0x800705AF` |
| HRESULT `0x800106BA` | Ошибка инструмента Defender; не подменять RPC-кодом `0x800706BA` |
| Таймаут CancellationToken | Уточнить отменён ли запрос наблюдения или само задание; текст исключения этого не доказывает |

Старший бит HRESULT показывает класс результата, но не выбирает пользовательскую тяжесть. Например, `0x80242014` означает незавершённую постзагрузочную обработку; карточка может требовать ожидания/перезагрузки, а не красного сбоя. Некоторые `*_BASE` и `BG_E_ERROR_CONTEXT_*` — служебные маркеры, не самостоятельные причины.

## Неизвестный или редкий код

1. Нормализовать signed/unsigned 32-bit без потери исходной записи и пространства кода.
2. При точном совпадении использовать русскую карточку; причины из справочника показывать как возможные.
3. Если известно только техническое имя: прямо написать, что подробная диагностическая карточка ещё не подготовлена. Не подставлять универсальное «очистить кэш».
4. Для Win32 допустим `FormatMessage(FROM_SYSTEM)` с учётом модуля и версии ОС. Текст сообщения не является доказательством первопричины.
5. При отсутствии описания — системное сообщение/символ из текущего журнала, затем кнопка поиска по точному коду. Не отправлять полный журнал, имена клиентов, пути и учётные данные в поисковый запрос. Поиск не выполняется автоматически этим прототипом.
6. Найденное в интернете описание не становится исполняемым рецептом. Обновление встроенного каталога через проверяемую версию; не загружать команды с произвольных страниц.

## Политика действий

Справочник не даёт разрешение на автоматический ремонт: `automatic_repair_allowed=false` для каждой карточки. Разрешения глобального автообслуживания, условия готовности клиента, пределы повторов и особые подтверждения должны проверяться отдельным механизмом приложения. Они не выводятся из наличия кода.

Ни один код сам по себе не разрешает удаление DataStore/WinSxS, сброс SusClientId, обход GPO/стоимости сети, отключение проверки TLS/подписи, завершение общего svchost или незапрошенную перезагрузку. Восстановление отчётности EventCache требует отдельного подтверждения старого отчёта и проблемной очереди, а не одного HRESULT.

Политики и наличие подходящего источника существенны: DISM RestoreHealth не гарантирован при блокированном интернете; сброс Download не исправит BITS cost policy. Документы Azure использованы для определений CBS/PSFX, а рекомендации восстановления VM не перенесены автоматически на обычные ПК.

Для `0x80244010` round trips не равны числу обновлений/метаданных из общего количества. Универсального обязательного ожидания между повторами справочник не заявляет: пауза и число попыток — политика приложения. Не очищать накопленный кэш перед каждым повтором.

## Проверка и использование офлайн

Только Python 3, без внешних зависимостей:

```sh
python build.py
python -m unittest -v test_reference.py
python lookup.py 0x800F0988 --domain hresult
python lookup.py --domain hresult -- -2146498168
python lookup.py 1455 --domain win32
python lookup.py 1 --domain exit --program cmd.exe
```

Это прототип справочного поиска, не команда удалённого ремонта. Во время работы он не обращается в сеть.

## Обновление

Извлечённые пары и русские карточки изменяются отдельным review, `build.py` детерминированно создаёт JSON/Markdown и контрольные суммы. Для каждого нового кода нужны официальный источник, проверка символа, границы применимости, отличия от обёрток и проверка отсутствия опасного автоматического совета. Полнота относительно всех существующих кодов Windows не заявляется.
