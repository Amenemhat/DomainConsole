# Изолированный стенд AD и WSUS

Стенд создаётся на время проверки. Конфигурация хранится в ветке `lab/0.57-wsus`. Для повторения точного прогона откройте [историю стенда](https://github.com/Amenemhat/DomainConsole/actions/workflows/wsus-lab.yml), выберите нужный запуск и нажмите **Re-run all jobs**. Учётная запись домена создаётся заново при каждом запуске. Доступ к рабочему домену не требуется.

| Узел | Назначение |
|---|---|
| DCAD | Контроллер леса `dc057.test`, две OU и запуск портативной консоли |
| DCWSUS | WSUS, IIS, WID, группа клиентского назначения |
| CLONE1–CLONE5 | Пять отдельных установок Windows с индивидуальными именами, аппаратными UUID и дисками |

Гости соединены частным коммутатором без внешнего шлюза. На хосте скачиваются официальный ознакомительный образ Windows Server 2022, подписанный сетевой драйвер и архив приложения из успешной сборки `main`. Принятый архив сверяется с опубликованным для него SHA-256. [Версия исходников для прогона](../../.github/lab/app-source)

У одного клиента Windows создаёт регистрацию. Ещё четырём на этом стенде задаётся тот же исходный ID. Консоль проверяет область AD, когда пятый клиент выключен из сети. После отдельного согласия оператора исправляются доступные участники. При возврате пятого подтверждается расширение группы. Итог сверяется с записями WSUS по новым ID, именам, группе и времени отчёта. Отдельно проверяется изменение времени загрузки Windows после команды из шапки консоли.

В артефакте `isolated-wsus-evidence` сохраняются завершённые стадии, идентификатор сборки, наблюдения WUA и WSUS, замеры процессов и результат проверки перезагрузки. При сбое указаны достигнутая стадия и причина, если её удалось прочитать. Диски виртуальных машин и пароли в артефакт не входят.

[Проверка регистрации на одной Windows](https://github.com/Amenemhat/DomainConsole/actions/workflows/standalone-wsus.yml) работает независимо. Она поднимает WSUS и проверяет реальную смену ID, получение нового отчёта и группу. Её результат относится к одному участнику.
