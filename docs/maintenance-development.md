# Обслуживание клиентов: изменения после 0.29

Изменения реализуются по Issues #31, #32 и #33. Это описание разработки, не опубликованный релиз. Установка исходников из main не заменяет проверенный пакет Releases.

## Актуальность перезагрузки

Время последней загрузки ограничивает срок действия положительных признаков: сведения, полученные раньше новой загрузки, остаются историей. Свежая полная проверка без флагов снимает прежнее требование. Неизвестный результат не считается положительным. Старое положительное подтверждение при неполном опросе сохраняется только при совпадающем известном времени загрузки.

Снимок WUA/реестра/аптайма собирается ограниченной задачей под SYSTEM через существующий защищённый механизм Probes. Завершённые задачи и временные каталоги удаляются. Ошибка опроса не меняет состояние сети. В журнале показывается один эпизод ошибки и время первого/последнего наблюдения; полный текст свёрнут. Успешный следующий опрос снимает предупреждение.

После обнаружения новой загрузки, завершившей прежнее требование, создаётся сохраняемое однократное продолжение поиска и запроса отчёта. Выполнение не зависит от выбранного компьютера. Обычный обзор статусов не разрешает установку.

## Отключённые записи AD

Отключение учётной записи (`userAccountControl & 2`) отображается серым именем и отдельным значком. В меню статусов есть фильтр с количеством и сохраняемый переключатель показа отключённых записей. Массовое подтверждение исключает такие цели и показывает число пропущенных; явный ручной запуск на текущем компьютере разрешён. Связь WinRM и сохранённая сводка WSUS не стираются.

## Последовательности

«Очистить кэш»: проверка занятости → остановка UsoSvc, wuauserv, bits, cryptsvc → выбранная очистка/копия → запуск всех существующих служб → поиск обновлений → запрос отчёта. Если подготовка/очистка/запуск служб завершились ошибкой, поиск не запускается. Принудительное завершение процессов автоматически не выполняется.

«Полное обслуживание…»: явное разрешение установки на точных целях → поиск, загрузка и установка → свежая проверка reboot → запрос отчёта. При требовании перезагрузки сохраняется ожидание; перезагрузка выполняется пользователем или отдельно разрешённым способом. После подтверждённого возврата и паузы готовности сценарий продолжает обслуживание. Сам режим не разрешает перезагрузку, принудительную остановку или очистку.

Лимиты: до трёх циклов на сценарий, срок продолжения до двух суток. Неудача/отмена прекращает повтор; при неполной проверке перед следующей установкой требуется решение. Уже выполняющаяся установка не прерывается по лимиту сценария. Перед продолжением проверяются идентичность цели, отсутствие другого задания WSUS и готовность установщика.

Планы сохраняются в `Data/maintenance-plans.json`; идентификатор продолжения сохраняется до помещения в историю и очередь. После закрытия программы уже переданные задания работают на клиенте; новые продолжения исполняются после открытия консоли. Дубли одного продолжения не создаются. Кнопка «Требуют внимания» открывает список ожидающих действий и позволяет открыть клиент или прекратить автоматическое продолжение, не отменяя уже запущенную операцию.

Получение серверного отчёта остаётся отдельным ограниченным ожиданием: успешное выполнение команды отправки не доказывает приём сервером.
