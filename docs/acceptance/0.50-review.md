# 0.50 — сверка статусов, отчётности и истории

Область: 27 Issues / 150 действующих условий из release-batches.json. До заполнения итоговой приёмки этот документ описывает методы и решения, а не пройденные испытания. Итог привязывается к точному main-коммиту, Windows run и SHA-256 выпускаемого ZIP.

## Поздние согласования

- #112/#104: положительные флаги не истекают через пять минут; новая загрузка требует повторной проверки. Более новая полная отрицательная проверка учитывается. Неполный ответ не снимает сохранённое положительное свидетельство.
- #112: подтверждённая полная готовность сохраняется при одном старении, вместе с исходными временами и идентичностью. Это не утверждение о непрерывной доступности клиента.
- #112: три критерия со значками, без нумерации и внутренних рамок; служебный сборщик не подменяет результат обновлений. Действия и фильтры — в согласованных заголовках/у соответствующей причины.
- #129: новый фильтр основных/служебных событий заменяет прежнее предложение только «Все/Ошибки/Замечания». Сырые события сохраняются. Результат очистки важнее промежуточных фаз, но остаётся в хронологическом порядке.
- Глубокая экспериментальная диагностика CBS-манифестов не включена в продукт по позднему решению владельца. Ошибка прямого XML-чтения сжатого манифеста не объявляется повреждением.

## Контракт WSUS и границы

Read-RequiredUpdates31 применяет LatestRevisionApproved/Install, затем эффективное Install для клиента; группирует строки по UpdateId. Дочерние installable items дополнительно не обходятся и не прибавляются. IsSuperseded сам по себе не исключает применимое одобренное обновление. Основание — контракт [GetUpdateInstallationInfoPerUpdate](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/aa349579(v=vs.85)), [Approve](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/ms747134(v=vs.85)) и [Decline](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/bb294934(v=vs.85)). Доменный сервер WSUS владельца недоступен; API-проверки используют подставные ответы, реальные корпоративные групповые политики не проверялись.

Резкое завершение агента реально, стадии WUA — тестовые. Новая загрузка задаётся контрольными снимками и сверкой Windows; реальное отключение питания во время установки CBS не выполнялось. VPN/обрывы и запоздалые ответы моделируются, локальные WinRM-сеансы настоящие. Проверки служб и кэша используют временные каталоги и подставные службы. Скриншоты показывают фактическую WPF-отрисовку, а не дизайн-макет.

Причина исторического `0xFFFF0000` требует журналов именно сбойного задания; #120 остаётся открытой. Влияние всех возможных доменных политик, драйверов и обновлений стенд не доказывает. Остальные порции остаются в своём плане.
