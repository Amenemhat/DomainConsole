## Правило выпуска

1. Фиксировать область и зависимости; для каждого условия иметь код, сценарий, ожидание, фактический результат и доказательство.

3. Привязать отчёт к точному исходному коммиту, прогону и SHA-256 ZIP. Обновить валидатор области порции с тестами запрета пропусков/дубликатов и обхода обязательных сценариев; до этого новый формат не использовать для публикации.
4. Остальные требования остаются pending в назначенных следующих порциях. Не объявлять их выполненными ради зелёного отчёта.
5. Закрывать Issue только при приёмке всей актуальной постановки. Если часть заменена поздним согласованием, указать замену явно.
6. Для каждого выпуска сообщать: исправлено/подтверждено ранее реализованное, принято условий из области, тесты, ограничения, закрытые задачи и следующий пакет. Процент общей готовности не вычислять из числа частичных доказательств.
