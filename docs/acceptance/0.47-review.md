## Решение о выпуске

**Публикация не выполнена; функциональные Issues по этому прогону не закрывались.** Реестр содержит 105 задач, но построчная повторная приёмка всех их действующих условий не завершена. Этот документ не является `0.47.json` и не предназначен для прохождения acceptance_gate.py.

Блокирующие пробелы: реальное аварийное прерывание на изолированной Windows VM; сброс кэша с зависшей остановкой/восстановлением служб и исчерпанием бюджета; полный сетевой сценарий A/B/C с автоматическим продолжением (управляемая задержка UI уже проверена); завершение сверки реестра. Для установления причины клиентского 0xFFFF0000 нужен исходный stderr/журнал конкретного сброса, а не один итоговый код.

Полная приёмка требует доступного изолированного Windows-стенда с управляемой перезагрузкой/выключением. Производственные компьютеры для разрушительных проверок не использовались. Нельзя заменить эти пробелы формальным passed или массовым закрытием задач.

## Продолжение проверки 28.10: тайм-ауты, потеря исполнителя и уведомления

Предыдущий раздел описывает исторический прогон, а не последний исходный код. Дальнейшие изменения не закрывают автоматически все 105 задач.

### Найдено и исправлено при сверке

- `ServiceRecovery47`: перед изменением службы защищённый шаг оставляет намерение восстановления. После жёсткого тайм-аута дочернего PowerShell агент восстанавливает записанные службы через ServiceController, даже если PowerShell finally не выполнился. Первичная ошибка сохраняется вместе с отдельной ошибкой восстановления. Восстановление не завершает процессы служб и не меняет тип запуска.
- `InterruptedServices47`: для гибели самого агента сохраняется PID и время создания его PowerShell. При следующем согласовании проверяются отсутствие исполнителя/его дочернего процесса, неработающая задача и свободный WUA. Сначала восстанавливаются допустимые записанные службы; только затем допускается согласование прерванного задания. Неизвестная идентичность, живой процесс и ошибка восстановления оставляют отказ. Старый сброс/установка не повторяются, исход остаётся неизвестным. Отдельный CacheCleanup без последующего Updates также охвачен.
- Ошибка восстановления служб в терминальном состоянии больше не делает задание автоматически свободным. Подтверждённое позднее восстановление снимает только это препятствие и не превращает прерванную операцию в Completed. Это восстановление при следующем обращении к управлению; новый постоянно работающий watchdog/задача не создаются.
- CacheCleanup/ReportRecovery прекращают последующие шаги даже при ContinueOnError. ReportRecovery сохраняет первичную ошибку, если finally тоже завершился ошибкой. Код исполнителя 124 имеет явное описание тайм-аута/прерывания и не трактуется как код Windows Update.
- Обновление остановленного Maintenance учитывает изменение хеша бинарного файла при той же версии; более новая версия, активная работа, чужие путь/аргументы/principal/hash защищены.
- Цели массовой очистки сборщика, включая endpoint/параметры, фиксируются до подтверждения/первого await. Изменение профиля во время последовательной очереди не перенаправляет оставшиеся операции.
- Просмотр фактического компактного WPF-снимка обнаружил наложение уведомления на сведения WSUS/связи. Прежний тест проверял только кнопки рабочей области. Уведомление теперь ищет свободное место в шапке; при недостатке места используется компактный значок с полным текстом по наведению/нажатию. Узкое место под него постоянно зарезервировано, появление уведомления не меняет высоту. Проверка учитывает пересечение всех видимых текстов, кнопок и значков шапки, а не только нижнюю границу.
