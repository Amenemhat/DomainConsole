## Объём

## Первый пакет

- Видимая причина задержки отчёта, измеренная очередь в подсказке, действие восстановления у отчёта. Неполная проверка не означает пустую очередь.
- Восстановление → проверка обеих очередей → поиск и запрос отчёта. Подтверждение приёма остаётся отдельным серверным фактом.
- При Auto ON разрешённый план продолжает установку после поиска. Завершённый/остановленный план автоматическим ремонтом не возобновляется.
- Короткий обрыв сохраняет наблюдение за прежним заданием. Долгий обрыв требует нового поиска перед следующей установкой; действующий исполнитель не дублируется.
- Поиск не расходует цикл установки.
- Ожидание допуска агента ограничено; контрольная точка сохраняется перед выходом, повторная активация того же задания не повторяет команду.
- Команды запроса отчёта ограничены отдельно от установки. Завершение системной установки из-за потери связи не добавлено.

Технические начальные пределы: 10 минут для обязательного контрольного поиска после обрыва, 5 минут ожидания допуска, 30 секунд для каждой команды запроса отчёта. Это выбранные параметры реализации, не ранее согласованные владельцем обязательные числа.

## IP/VPN — уточнение владельца 02.11

Подтверждённая IP-привязка теперь передаёт успешное наблюдение в общий статус связи. Ручное действие WSUS при старой/потерянной связи проверяет сохранённый IP до диагностики Windows Update. Проверка WinRM ограничена существующими 30 секундами, одновременные обращения объединяются, после отказа повторный ручной запрос не создаёт новую проверку в течение минуты. Фоновый опрос сохраняет интервалы 2/5/15 минут; новых фоновых циклов не добавлено. Минутная пауза — выбранный параметр реализации. Смена endpoint/identity и master OFF отбрасывают старые ответы.

Новые условия 134.ip-connect, 134.ip-bounds, 134.ip-stale; VerifyIpReconnect52 проверяет переходы и количество вызовов с изолированными ответами. Реальное подключение производственного VPN этим тестом не заменяется. Требуется Windows run новой редакции.
