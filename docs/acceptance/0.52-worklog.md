# 0.52 — рабочая сверка, не приёмка релиза

Согласование: issue #134 и последующие уточнения владельца в текущем диалоге. PR #135.

## Объём

37 задач / 150 условий из `release-batches.json` для 0.52. Отдельная проверка SusClientId (#6) остаётся в ранее согласованной порции 0.53. Исторические причины инцидентов #113 и #120 не считаются установленными этой работой.

## Первый пакет

- Видимая причина задержки отчёта, измеренная очередь в подсказке, действие восстановления у отчёта. Неполная проверка не означает пустую очередь.
- Восстановление → проверка обеих очередей → поиск и запрос отчёта. Подтверждение приёма остаётся отдельным серверным фактом.
- При Auto ON разрешённый план продолжает установку после поиска. Завершённый/остановленный план автоматическим ремонтом не возобновляется.
- Короткий обрыв сохраняет наблюдение за прежним заданием. Долгий обрыв требует нового поиска перед следующей установкой; действующий исполнитель не дублируется.
- Поиск не расходует цикл установки.
- Ожидание допуска агента ограничено; контрольная точка сохраняется перед выходом, повторная активация того же задания не повторяет команду.
- Команды запроса отчёта ограничены отдельно от установки. Завершение системной установки из-за потери связи не добавлено.

Технические начальные пределы: 10 минут для обязательного контрольного поиска после обрыва, 5 минут ожидания допуска, 30 секунд для каждой команды запроса отчёта. Это выбранные параметры реализации, не ранее согласованные владельцем обязательные числа.

## Проверки

Первый Windows run: https://github.com/Amenemhat/DomainConsole/actions/runs/41053125504 (исходники 509ed8e223c13f4d9005e2c3d7c4f7faf834a103). На момент записи скомпилировано; прошли ограниченное ожидание реального агента, прерывание агента, восстановление после таймаута, UI и сценарии продолжения. Полный run ещё выполняется.

Локальные тесты publication/acceptance scripts: 23 прошли. Это не проверка WPF и не итоговая приёмка.

Следующая редакция дополнительно проверяет кнопку очереди на Windows, запрещает возобновление любого завершённого плана при автоматическом ремонте, уточняет свежесть отчёта относительно ремонта и ограничивает команды запроса отчёта. Для неё требуется новый полный run.

## Ещё не принято

- Полная проверка каждой из 150 действующих спецификаций с учётом поздних комментариев, а не только diff.
- Просмотр фактических снимков нового действия отчётности, матрица взаимодействий и измерения текущей сборки.
- Полный итоговый Windows run на неизменном исходном коммите и машинный отчёт приёмки с хешем ZIP.

Ни одна задача 0.52 не закрывается этим журналом. Это контрольная точка работы; выпуск не опубликован.
