# Сверка требований 0.47: покрытие и открытые пробелы

Это рабочая карта 105 задач, а не отчёт успешной приёмки. Все постановки включены в `0.47-condition-inventory.json`, со ссылками и контрольными суммами исходных блоков и комментариев. Для каждого направления указаны код и проверочные файлы. **Список проверочных файлов не доказывает покрытие каждого условия. Ни одна задача этим документом не закрывается.**

## Поздние согласования

- #1: Возраст сам по себе не отменяет последнюю полную готовность; поздние #112/#115 заменяют старое правило синей галочки.
- #11: Выбрать все относится к обычным службам; отдельный принудительный выбор процессов #78 — Ctrl/Shift без галочек.
- #20: Запрет постоянного задания заменён согласованным единым сборщиком #113–#118 с автономным пределом и запретом дублей.
- #21: После возврата сначала свежие факты/поиск; установка только при сохранённом согласии и актуальных результатах (#39/#114).
- #27: Заливка/анимация только реальной рабочей операции; служебное чтение — текст (#115/#112).
- #31: Неполнота не означает false. Положительное свидетельство сохраняется в той же загрузке до новой проверки; после нового boot нужна проверка (#112).
- #45: Макет #91/#96/#99 заменяет раннее размещение действий/событий: OS под именем, вкладки справа, режимы на всю область.
- #47: Палитра уточнена #98; расположение — #91/#96/#99, три темы сохраняются.
- #53: История ниже основной карточки, фон отдельным свернутым блоком; инструменты только в заголовках (#93/#112).
- #55: Вкладки справа над действиями, не отдельная строка под шапкой (#91/#99).
- #58: Служебный опрос не получает анимацию рабочей установки (#115/#112).
- #63: Кандидаты золотого цвета заменены принятыми #98: оранжевый текст, жёлтый значок; общая палитра.
- #67: Весь блок правой кнопки выровнен слева (#96); значок центрирован внутри своей фиксированной колонки.
- #70: Строки выделяются Ctrl/Shift, не галочками (#93). Поздний фильтр — dropdown в заголовке (#112).
- #72: Вкладки справа, настройки внизу отдельно от вертикальных Опрос/Авто (#91/#118).
- #73: Текущая операция показывает полное название обновления (#87); краткий KB допустим для сводки ошибки.
- #82: Убрать Пользователь/Последний; всегда имя и дата/время без секунд, жирное только имя (#91/#96).
- #93: Поздний фильтр: выпадающий список в заголовке вместо сохранённой в ранней постановке галочки (#112).
- #97: Рамки внешних журналов сохраняются; все раскрытия внутри главной карточки без рамок (#112).
- #104: Ожидание reboot не снимается по возрасту. В главной карточке три критерия; адресная проверка у критерия при неизвестности/нужной перепроверке (#112).
- #110: Три критерия #112 заменяют запрет отрицательной строки: подтверждённое отсутствие reboot зелёное внутри критерия; отдельной вложенной карточки нет.
- #114: Явное восстановление в шапке рядом со связью; успех только после свежего полного снимка; прерванная установка сначала согласуется и перепроверяется.
- #118: Опрос над Авто, настройки отдельно. OFF сохраняется, не завершает клиентские рабочие задания.

## Подтверждённые пробелы и ограничения

В requirements.json вручную выделены 504 актуальных условия всех 105 задач с учётом поздних уточнений. Индекс 1081 исходного блока сохраняет также исторический контекст; это не число требований или прошедших тестов. Регистрация условий завершена, их поусловная приёмка по коду и фактическим свидетельствам — нет.

- [#6](https://github.com/Amenemhat/DomainConsole/issues/6): Чтение SusClientId и серверное сопоставление есть; полный групповой поиск коллизий и подтверждаемая перерегистрация не реализованы. Открытая функциональная задача.
- [#44](https://github.com/Amenemhat/DomainConsole/issues/44): Hard timeout и потеря агента дополнительно обработаны ServiceRecovery47/InterruptedServices47; точные успешные прогоны и границы подстановки служб приведены в 0.47-review.md. Полная приёмка всех файловых отказов остаётся поусловной.
- [#61](https://github.com/Amenemhat/DomainConsole/issues/61): Восстановление при hard timeout дополнительно проверено с настоящим процессом PowerShell и подстановкой служб; это не доказательство причины конкретного клиентского сброса #120.
- [#88](https://github.com/Amenemhat/DomainConsole/issues/88): Конкурируют отдельные процессы на одном Windows-хосте; две реальные GUI-консоли в домене и все сочетания старых версий не испытаны.
- [#90](https://github.com/Amenemhat/DomainConsole/issues/90): Структурированные причины проверены; отдельной русской Windows VM нет.
- [#113](https://github.com/Amenemhat/DomainConsole/issues/113): Реальные ограниченные WinRM/SYSTEM прогоны есть; историческая причина исчерпания всех ресурсов не доказана одной симуляцией.
- [#114](https://github.com/Amenemhat/DomainConsole/issues/114): Резко завершается настоящий процесс агента на четырёх имитированных стадиях WUA; проверяется живой/мертвый исполнитель, занятость, release и свежий поиск. Это не отключение питания и не прерывание настоящего CBS.
- [#116](https://github.com/Amenemhat/DomainConsole/issues/116): Исправлены read-only Inspect, миграция после отказов, версия пакета47 и запрет отката; отдельной RU Windows и полного смешанного парка старых GUI нет.
- [#117](https://github.com/Amenemhat/DomainConsole/issues/117): Подтверждённые собственные объекты удаляются; чужие/неподтверждённые сохраняются с Partial. Все комбинации обрыва на каждом шаге массового удаления не испытаны.
- [#120](https://github.com/Amenemhat/DomainConsole/issues/120): Неизвестный exit сохраняет stderr и этап; 10 тестов сброса со службами-подстановками. Hard timeout и потеря агента исправлены и проверены отдельными сценариями ServiceRecovery47 на настоящих процессах с подстановкой служб; причина конкретного клиентского сброса остаётся непроверенной без его исходных журналов.
- [#122](https://github.com/Amenemhat/DomainConsole/issues/122): Реальный WPF с управляемой задержкой A/B/C и pipeline автопродолжения проверен; полный сетевой A/B/C сценарий с физической перезагрузкой не проведён.
