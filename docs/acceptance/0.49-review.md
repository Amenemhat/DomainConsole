# 0.49 — прерывание обслуживания и безопасное продолжение

Область: 20 Issues / 105 действующих условий из release-batches.json, плюс все обязательные регрессии. Этот документ описывает сверку и границы испытаний; сам по себе не является разрешением публикации. Итоговый отчёт привязывается отдельно к исходному коммиту, Windows run и SHA-256 ZIP.

## Поздние согласования

Условия 33.mode и 39.authorization приведены к [решению владельца от 18.10](https://github.com/Amenemhat/DomainConsole/issues/39#issuecomment-6253360266): общий сохраняемый «Авто», включённый по умолчанию, разрешает полный цикл; OFF оставляет одну операцию. Раннее «без установки по умолчанию» больше не является действующим условием. В подтверждении теперь показан полный цикл и при включении через общий «Авто», а не только через отдельную кнопку.

## Исправления, выявленные при сверке

- Диагностический поиск не расходует лимит трёх установочных попыток. После третьей попытки разрешена свежая проверка результата, но не четвёртая автоматическая установка.
- После новой загрузки полный план мог сразу ставить установку. Теперь сохраняется намерение сначала выполнить поиск; true/null флаги не блокируют этот диагностический поиск, но не разрешают последующую установку.
- Удалённый/заменённый план, смена endpoint, выключение опроса и отмена будущих шагов во время ожидания больше не допускают отправку по запоздавшему ответу.
- Выключение «Авто» сохраняет отмену reboot-followup, включая уже завершённое наблюдение и ещё не отправленное задание. Неподтверждённый ранее план shutdown не должен снова включить продолжение.
- Для старого задания без status.json согласование возможно только после подтверждённой новой загрузки, проверки собственной задачи/исполнителя и свободного WUA. Результат — неизвестный исход, не успех установки. В той же загрузке отсутствие результата не освобождает запись.
- Автоматический ремонт EventCache заканчивается поиском/запросом отчёта; глобальное «Авто» не расширяет этот ремонт до установки.
- Сброс кеша проверяет существующие родительские каталоги, различает исчезновение и другие ошибки переноса, регистрирует каждый отделённый каталог. Не запускает физическую очистку резервных копий/отсутствующих каталогов и не заявляет о фактическом сбросе без изоляции.
- Принудительный выбор отвергает противоречивые снимки одного PID; адресат фиксируется до чтения списка. Перед завершением повторно проверяются PID, время, путь, критичность, службы и зависимости. В диалоге показана последняя известная активность установки с временем либо отсутствие подтверждения.
- Диагностика IP разделяет DNS (для имени), маршрут/TCP, HTTPS/TLS, открытие PSSession/аутентификацию и чтение идентичности. Отказ TCP не объявляется неверным паролем. Есть копирование сравнимой команды для Windows PowerShell без пароля и изменения доверенных узлов.

## Границы доказательств

- Резкое завершение тестового агента выполняется реально на стадиях поиска, скачивания, установки и перед записью результата; сам WUA подменён. Новая загрузка проверяется снимками и сверкой времени реального Windows runner. Это не отключение питания доменной виртуальной машины во время настоящей установки.
- Восстановление служб проверяется с настоящими дочерними процессами и журналами намерений, но службы заменены тестовыми обработчиками. Производственные службы и клиенты не затрагиваются.
- Локали ru-RU/en-US проверяют культуру процесса и русский структурированный результат в PS5.1; это не два отдельных образа Windows с разными языковыми пакетами.
- Реальные домен, VPN, корпоративные TLS-сертификаты и WSUS владельца недоступны стенду. TCP доказывает достижимость порта, а не исправность каждого маршрута; TLS не проверяет разрешение WinRM входа.
- Причина исторического 0xFFFF0000 без журналов именно сбойного задания остаётся неизвестной. Исправления диагностических и восстановительных границ не доказывают эту причину. #120 остаётся открытой для расследования конкретного инцидента.
- Остальные порции 0.50–0.53 не объявляются принятыми этим выпуском.
