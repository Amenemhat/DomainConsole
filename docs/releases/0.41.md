# DomainConsole 0.41

## Ограниченный опрос и защита от накопления ресурсов

- Вместо новой задачи `DomainConsoleCSharp-Probe-<GUID>` на каждый опрос используется одна задача `DomainConsoleCSharp-Snapshot41` на клиенте. Она собирает общий снимок флагов, аптайма, пользователя и фоновой активности под SYSTEM. У задачи нет расписания; запуск только по запросу, лимит выполнения 40 секунд, параллельные экземпляры запрещены.
- Снимок переиспользуется до 45 секунд. Блокировка файла на клиенте согласует разные управляющие компьютеры. При неизвестном результате сохраняется запрет повторного запуска; автоматическая лавина новых задач исключена этим механизмом. Возобновление — отдельная команда после проверки, работающий сборщик не прерывается.
- До запуска PowerShell действует общий лимит трёх подключений на экземпляр и исключение перекрытия одного endpoint между экземплярами консоли одного пользователя на управляющем компьютере. Тайм-аут подключения ставит endpoint на паузу до явного возобновления. Сеансы WinRM получают idle timeout 60 секунд; принудительное завершение локального ожидания не объявляется отменой удалённого обслуживания.
- Кнопка «Пауза опроса» приостанавливает новые подключения этого экземпляра. Уже переданные задания продолжаются. Другие экземпляры и старые версии этим не выключаются.
- «Диагностика и восстановление → Опрос и остатки Probe…»: предварительный список и удаление только завершённых Probe старше 10 минут с проверяемой старой сигнатурой. Отсутствие каталога не мешает удалению, если возраст подтверждается регистрацией/последним запуском. Действующие, свежие и неизвестные задачи пропускаются. Перед изменением повторно проверяется состояние. За один запрос рассматриваются не более 500 задач.
- Maintenance, рабочие задания обслуживания, каталоги и процессы WinRM эта очистка не удаляет. Массового завершения PowerShell/WinRM нет.

## Согласованный текущий статус

- Главная плашка, «Главное», дерево, последние компьютеры, фильтры и список внимания используют общий расчёт текущей готовности. Ход активной операции сохраняется, существенные проблемы показываются рядом.
- Свежий отчёт, принятый до окончания служебных действий задания, больше не объявляется недоставленным только по сравнению с `Ended`. Связь отчёта с отдельным вызовом Report остаётся технической подробностью.
- Полная зелёная готовность требует полного серверного подсчёта с нулевым остатком, свежего отчёта, актуального успешного поиска клиента с нулевым остатком, полной свежей отрицательной проверки перезагрузки и отсутствия актуальных ошибок/операций. При отсутствии подтверждения указано, чего именно не хватает. Само перечитывание старых данных не освежает их.
- Свежая подтверждённая необходимость перезагрузки становится основным результатом с источниками и временем. Вложенная карточка убрана. Отрицательная проверка не создаёт отдельной плашки.
- Возраст отчёта пересчитывается из исходной отметки без новых сетевых запросов. Время административного чтения сохранено отдельно; запоздалые ответы и смена endpoint не должны затирать более новые данные. Исторический результат задания остаётся отдельным результатом.
- В информационных подписях адреса только IPv4. IPv4-mapped IPv6 корректно преобразуется через `MapToIPv4`; настоящий IPv6 скрыт в этих подписях, подключение по IPv6 сохраняется.

## Проверка

Публикация допускается после успешной Windows-сборки точного коммита, проверки интерфейса в трёх темах и четырёх режимах, тестов реального SYSTEM/WinRM, конкурирующих запросов, остановки сборщика по лимиту, запрета повторов после неизвестного исхода и избирательной очистки. Проверки выполняются на отдельной машине CI; это не диагностика производственных серверов.

## Обновление

1. Закройте **все старые экземпляры** DomainConsole на управляющих компьютерах. Новая версия не может запретить обращения продолжающей работать старой версии.
2. Распакуйте новый пакет в отдельную папку и перенесите прежнюю папку `Data`, если меняете расположение программы. Архив выпуска не содержит пользовательских данных.
3. При необходимости проверьте известные серверы по одному через «Опрос и остатки Probe…», просмотрите список и удалите только подтверждённые остатки. Не запускайте массовую очистку всех задач DomainConsole.
4. После паузы конкретного клиента проверьте причину и воспользуйтесь «Возобновить опрос клиента». Эта команда не останавливает обслуживание и не завершает неизвестные WinRM-процессы.

Связанные задачи: #110, #111, #112, #113. Развёртывание на производственных серверах не выполняется публикацией пакета.
