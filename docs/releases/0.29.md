# DomainConsole 0.29

## Перезагрузка и навигация

- Отправка команды shutdown и новая загрузка Windows различаются. Результат отправки, последний ответ и время загрузки показаны отдельно. Прежняя загрузка через пять минут после срока — явное предупреждение; неизвестные флаги не мешают подтвердить новую загрузку (#26).
- Наблюдение опрашивается отдельным таймером, получает план независимо от очереди результатов. Сохранённый срок не переносится вперёд при позднем чтении. Смена подтверждённой идентичности прекращает наблюдение. Автоматического повторного reboot или включения /f нет.
- Прогресс последних компьютеров — полупрозрачный фон строки; текст и значки остаются поверх, обработка выбора сохранена (#27).
- Подсказка значка действует по всей площади 18×18. Неизвестное состояние имеет непустое пояснение и следующее действие (#29).

## Подключение

- Настройки → «Учётные данные подключения…»: текущая личность Windows либо одна общая запись для разных клиентов. В параметрах клиента доступна отдельная запись (#30).
- Пароль по явному выбору сохраняется в Credential Manager Windows, для того же пользователя на том же компьютере. Папка Data не содержит пароль. Доступны изменение и удаление общей/индивидуальной записи. Сетевой сбой не удаляет её.
- «Подключить и сохранить» проверяет разрешение конкретного IP для HTTP. При необходимости одно подтверждение добавляет только указанный адрес, сохраняя остальные. Проверка без сохранения вынесена в дополнительный раздел. HTTPS не требует изменения TrustedHosts.
- Отдельно показаны TCP WinRM, открытие сеанса/аутентификация и чтение имени/идентификатора. Код 0x8009030e не объявляется автоматически неверным паролем; таймаут не вызывает повторный запрос.

## Обновление и ограничения

Закройте приложение и замените DomainConsole.exe и каталог Agent; сохраните свою Data. Старые переданные задания используют свой прежний сценарий. Улучшенная квитанция отправки shutdown появляется у новых заданий; для старых доступно наблюдение времени загрузки.

Текущий вход без пароля работает при поддержке выбранного пути и политик Windows. В стандартном PowerShell Remoting прямой IP использует NTLM и может требовать явный Credential даже для доменного администратора; используйте общую запись либо корректно разрешаемое доменное имя. Программа не изменяет DNS/SPN, не отключает проверку сертификатов и не добавляет wildcard в TrustedHosts. Членство в домене и открытый TCP-порт сами по себе не гарантируют успешный WinRM.

Проверки CI не заменяют проверку реального VPN/AD/WSUS. Причина конкретной задержки перезагрузки на клиенте не устанавливается без его журнала; новый вывод отделяет подтверждённые факты от ожидания.
