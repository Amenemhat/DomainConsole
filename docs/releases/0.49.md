# DomainConsole 0.49

Вторая порция после 0.48: восстановление прерванного обслуживания, безопасная очистка и согласованное управление клиентом. Остальные задачи остаются в плане следующих выпусков.

## Что исправлено

- Диагностический поиск не расходует лимит трёх установочных попыток; после последней попытки результат всё равно проверяется.
- После перезагрузки полный план сначала выполняет свежий поиск обновлений. Старый процент установки не используется для продолжения, неоднозначный флаг перезагрузки не блокирует диагностический поиск бессрочно.
- Задание без конечного результата можно штатно согласовать после новой загрузки и проверки отсутствия исполнителя, собственной работающей задачи и занятости WUA. Исход прежней установки остаётся неизвестным до проверки.
- Выключение «Авто» сохраняет отмену будущих шагов, включая отложенный поиск после перезагрузки. Запоздавший ответ, замена плана или смена endpoint не создают новое задание.
- Восстановление очереди отчётности заканчивается поиском и запросом отчёта; оно не включает установку само по себе.
- Сброс кеша проверяет ссылки во всей цепочке каталогов, сохраняет сведения о частичной изоляции и различает исчезнувший каталог, ошибку переноса и ошибку запуска службы. Нет сообщения «кэш сброшен», если переноса не было. Резервные копии не отправляются в фоновое удаление.
- Ручное завершение процессов служб отвергает противоречивые снимки одного PID и повторно проверяет адресата. В подтверждении показана последняя известная активность установщика либо отсутствие её подтверждения.
- Проверка IP-подключения отдельно показывает DNS, маршрут/TCP, TLS, сеанс/аутентификацию и идентичность. Можно скопировать сравнимую проверку для PowerShell без пароля и изменения настроек доверия.
- Подтверждение запуска при включённом «Авто» прямо указывает полный цикл обслуживания, согласно позднему согласованию владельца.

## Приёмка

Область порции: 20 задач / 105 условий и 11 обязательных регрессионных сценариев. Точный коммит, Windows run, хеш ZIP и поусловные доказательства находятся в [отчёте 0.49](https://github.com/Amenemhat/DomainConsole/blob/main/docs/acceptance/0.49.json). [Описание испытаний и ограничений](https://github.com/Amenemhat/DomainConsole/blob/main/docs/acceptance/0.49-review.md).

Проверки включают настоящее резкое завершение изолированного агента на четырёх стадиях, восстановление после тайм-аута дочернего PowerShell, конкурирующие процессы и WinRM-читатели, повторные действия, сохранённый OFF, русский UTF-8 в PS5.1, три темы и два размера окна во всех режимах. WUA и системные службы в разрушительных сценариях подменены: производственные клиенты не затрагивались. Отключение питания во время настоящей установки в домене этим стендом не воспроизводилось.

Причина исторического клиентского `0xFFFF0000` без журналов именно сбойного задания остаётся неизвестной. Исправлены подтверждённые границы диагностики/сброса; [#120](https://github.com/Amenemhat/DomainConsole/issues/120) остаётся открытой для расследования исходного случая.

## Обновление

Закройте консоль, сохраните резервную копию её папки `Data` и замените файлы приложения из ZIP. Существующую `Data` сохраните. Обновление консоли само по себе не разрешает повтор установки и не включает выключенный опрос.
