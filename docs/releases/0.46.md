# DomainConsole 0.46

Исправлено наблюдение за заданиями, которое могло задерживать обновление интерфейса до перезапуска консоли. Добавлено безопасное согласование записи прерванной операции; переработаны критерии готовности и заголовки журналов.

## Задания и защита клиентов

- Медленное чтение одного задания больше не удерживает общий цикл наблюдения за остальными. Сохранены максимум три фоновых читателя и одно ожидание на пару клиент/задание. Выключатель опроса отменяет ожидающие чтения.
- План обслуживания проверяется после согласования фактического состояния исполнителя. Исчезнувший исполнитель не оставляет план в состоянии «Выполняется» только из-за старого снимка.
- При проверке допуска, освобождении плана или ручной передаче управления восстанавливается запись прерванного задания: после подтверждённой новой загрузки Windows; для задания обновлений — также при исчезновении известного исполнителя в той же загрузке.
- Проверяются отсутствие работающей/ожидающей задачи и соответствующего процесса, незанятость установщика Windows Update, отсутствие незавершённого восстановления и давность состояния не менее двух минут. Изменение выполняется под общей блокировкой управления, исходный status.json сохраняется в резервной копии.
- Прерванная операция получает состояние «Требуется действие», результат остаётся неизвестным. Автоматическое продолжение и повтор установки для такого плана запрещены. Установщик, службы Windows Update/CBS и системные процессы автоматически не завершаются.
- Перед началом установки дополнительно проверяется занятость WUA. Защита самой Windows от конкурирующих установок сохраняется.

## Интерфейс и диагностика

- Критерии готовности раскрываются без рамок. Старая отрицательная проверка перезагрузки имеет нейтральный цвет; она не означает ошибку или новое требование перезагрузки.
- История: фильтр и три значка копирования находятся в заголовке. Поиск и действия журналов остаются в одной строке, включая узкое окно.
- Уведомление расположено справа сверху без сдвига содержимого; основные кнопки ниже остаются доступны.
- Подробности опроса свёрнуты и обновляются независимо от раскрытия истории. Рекомендованное действие перенесено в область результата.
- Подробности текущей операции не повторяют раздел «Главное»; технические сведения объединены. Исторический полный результат сохраняется.
- При отсутствии свежего состояния активного задания показывается ограничение наблюдения, последний этап и время. Это не выдаётся за подтверждённую остановку клиента.
- Поиск, скачивание и установка имеют разные значки. События разных ID заданий больше не сворачиваются в одну запись.
- Исправлено преждевременное сообщение об успешном сбросе кэша; увеличен общий предел сценария с учётом штатной остановки и восстановления служб.
- Добавлена проверенная карточка WOF 0x80071160. Неизвестный 0xFFFF0000 не получает выдуманную расшифровку.

## Ограничения и обновление

Возобновление установки с сохранённого процента не выполняется. После прерывания требуется свежая проверка результата Windows, затем осознанный новый запуск. Произвольные команды с неизвестным исходом в той же загрузке, отсутствующий/повреждённый status.json и незавершённое восстановление требуют отдельной диагностики. Проверка допуска не является автономным периодическим перезапуском задания.

Причина 0xFFFF0000 при сбросе кэша конкретного клиента пока не установлена; изменение сообщения и таймаута не считается доказанным устранением этой ошибки.

Закройте старые экземпляры консоли. Распакуйте пакет в отдельную папку и перенесите существующую папку **Data**. Не удаляйте рабочие каталоги агента и журналы клиента. Для ручной проверки управления используется меню подключения → передача управления; действие разрешается только после проверки состояния клиента. Если на клиенте нет агента этой сборки, сначала передайте диагностическое задание из новой консоли.
